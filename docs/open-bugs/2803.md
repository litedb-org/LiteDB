# Issue 2803: post-commit checkpoint failure masks the original error

The retained `EnsureIndex` regression reproduces on LiteDB **5.0.10 and dev
`a50661a9`**, three of three attempts each on Linux/.NET 8 on 2026-09-15.
A one-time access-denied error on the data stream occurs during the automatic
checkpoint after index creation commits. The caller instead receives
`LiteDB ENSURE: transaction must be active to rollback`.

Before checking that diagnostic, the test requires the committed index to exist,
a subsequent write and checkpoint to succeed, every original payload to survive
reopen, a secondary-index lookup to resolve the right ID, and uniqueness to reject
a duplicate. Swallowing the error or omitting index creation cannot pass.
The ordinary failed-unique-index rollback control remains alongside this test.

This proves the post-commit masking path identified in the issue's linked fork.
It does **not** establish the original reporters' `SynchronizationLockException`
or the cause of their damaged data. Those limits remain explicit.
