# Issue 2093: `Find(Expression)` returns no items while compiled LINQ finds them

Source: https://github.com/litedb-org/LiteDB/issues/2093 (open on 2026-09-13).

## Current disposition (2026-09-17)

At the user's request, close this incomplete original report without claiming a
fix. The concrete missing-field/CLR-default mismatch is tracked separately as
[#2912](https://github.com/litedb-org/LiteDB/issues/2912).

The complete fixture remains unchanged at
[`LiteDB.Tests/Issues/Issue2093_Tests.cs`](../../LiteDB.Tests/Issues/Issue2093_Tests.cs).
Its historical class/file name and known-failure mappings are preserved; the two
missing-field parity assertions and two fully persisted controls now provide
executable evidence for #2912. They are not proof of #2093's unknown predicate.
See [the new issue notes](2912.md). No production query behavior was changed.

## Reproduction boundary

The report does not contain the `User` model, the predicate passed to `Find`, a
sample document, the translated `BsonExpression`, or an exact LiteDB version.
The only supplied model detail is a non-nullable `Removed` property used by the
repository's in-memory `FindAll()` filter. The reporter has not yet answered the
request for the missing inputs, so the original case cannot be reproduced or
ruled out exactly.

The regression test therefore does not claim to be the reporter's predicate. It
first checks plausible translation differentials (case normalization, enum
encoding, a UTC date range, and a renamed BSON member) using fully persisted
typed documents. Those controls pass with both string and integer enum storage.

It then exercises a concrete nearby cause of the reported observable: a
persisted document with no `Removed` element materializes as CLR
`Removed == false`. The same predicate compiled and applied to `FindAll()` finds
the object, but its translated BSON comparison rejects the absent field and
returns no objects. The fixture creates the BSON independently, closes and
reopens the database, and verifies the raw field names, enum representation,
date type, and the deliberate absence of `Removed` before running either path.
An `_id` query and the predicate without `Removed` are healthy controls.
