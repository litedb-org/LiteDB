# Issue 2802: Overridden BsonMapper.ToObject is never called when reading through ILiteCollection<T> / ILiteQueryable<T> in v5

Source: https://github.com/litedb-org/LiteDB/issues/2802 (open on 2026-09-12).

## Observed on dev

Base: `90788bace880f477c9fb52ff7c0da98c9700bdfe`; Release, .NET 8, Linux.
`{'Failed': 10, 'Passed': 1, 'Skipped': 0}`. The original five
non-generic-override cases fail. The strengthened suite also uses a mapper that
overrides only `ToObject<T>`; all five typed read surfaces fail to return that
hook's sentinel-bearing object. The passing direct-conversion control proves
the override is callable and that the default mapper cannot synthesize the
ignored sentinel field.

## Independent anti-bypass checks

- The generic-only subclass does not override `ToObject(Type, BsonDocument)`.
  A fix must dispatch through `ToObject<T>`; the base generic implementation
  then continues to support subclasses that override the non-generic hook.
- The generic override records the requested type and source document ID and
  returns a distinct name plus a `[BsonIgnore]` sentinel. Each of `FindAll`,
  `FindById`, `Find`, `FindOne`, and `Query().ToList()` must preserve that exact
  result, so merely invoking and discarding the callback is not enough.
- The source row is inserted and re-read as raw BSON. It contains neither the
  sentinel nor the transformed name, excluding persistence as their source.
- A default `BsonMapper` control maps the same BSON document without the
  sentinel, while direct generic dispatch through the custom mapper produces
  it and records exactly one callback.
