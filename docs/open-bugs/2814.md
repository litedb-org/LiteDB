## Manual correction

Auto-checkpoint now joins the exclusive admission queue for up to 10 ms rather
than skipping immediately whenever another thread has a transaction. The existing
writer preference holds off new readers while current readers finish, allowing
checkpoint to make progress under continuous short reads. A timeout remains a
normal unsuccessful attempt; later commits retry. Current-thread transactions
still prevent an upgrade, and Rebuild's nonwaiting behavior stays unchanged.

The deterministic admission controls and 64 focused engine cases pass, alongside
51 runner cases. All ten retained
integrated production attempts pass, including every acknowledged payload after reopening.
This is a soft checkpoint budget: long transactions or a cursor retained on the
committing thread can still delay checkpoint. No hard WAL size cap is promised.

The runner keeps the current-source expectation strict (green, exit 10). Its
historical package leg uses the explicit intermittent observation expectation:
completed 0/10 outcomes with the repeat summary are accepted; harness errors
still fail. An all-pass historical run is not evidence that the defect vanished.

Concurrent explicit/writing transactions that require the engine lifecycle lock
to complete can make a checkpoint attempt time out too. This change targets
continuous query readers, whose leases can drain independently. A later commit
retries after other transactions release; the budget remains soft for these
workloads rather than extending checkpoint outside its lifecycle protection.

Transaction construction now takes its admission lease before reserving a WAL
ID, so a checkpoint cannot reset the ID sequence underneath a queued new
transaction. Constructor failures release that lease. The deterministic
checkpoint/ID test fails before this ordering change and passes after it.
