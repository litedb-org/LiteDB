# Issue 2912: typed queries and defaults for absent BSON fields

Source: https://github.com/litedb-org/LiteDB/issues/2912.

The user requested separate tracking after closing the incomplete original #2093
report. This concrete case is not claimed to be that report's historical cause.
It is separate design work outside the manual bug-fix sweep.

A document without `Removed` materializes into a plain non-nullable bool property
as false. In-memory `Removed == false` matches; the translated BSON comparison
does not match the absent field. Constructors, initializers, custom factories and
deserialization hooks can supply different defaults, so substituting CLR type
defaults globally would not establish parity.

## Questions for design

- Specify stored-BSON semantics versus explicitly mapped defaults in typed queries.
- Distinguish absent fields from stored null, false and true, and cover constructor
  or initializer values that differ from CLR type defaults.
- Assess index consistency, existing query compatibility, custom mapper hooks,
  and whether any new behavior must be opt-in.

The parity assertions preserve the observable mismatch; they do not decide the
future API or justify silently changing current BSON query semantics.
