## Manual correction

Index-based projections use the document lookup for date-bearing keys, including
nested documents and arrays. This applies the same UtcDate and sentinel decoding
as ordinary document reads, including existing files whose scalar index key
already lost sentinel information. Non-date keys retain the index-only fast path.
Date-bearing projections therefore require a document read.

Index encoding, comparison semantics, and DateTime truncation remain unchanged.
Changing those globally would reinterpret old DST-affected index links without a
rebuild. This correction deliberately preserves existing file interpretation and
keeps stored UTC instants when projecting local dates. An internal factory for
already-decoded dates preserves the hidden ambiguous-DST flag; public DateTime
construction and legacy index decoding remain unchanged. It does not
repair pre-existing lossy timestamp data or wrongly ordered indexes.

Tests cover pragma toggling, reopen, nested date keys, scalar MinValue/MaxValue,
near-bound UTC values, and agreement with document reads during repeated local
hours. Address-based aggregate/sort replay reloads the data block, rather than
interpreting it as an index-node address. Tests also cover multiple aggregates,
computed sorting, and distinct repeated-hour groups on correctly ordered indexes.
All 14 focused cases pass in America/New_York and Pacific/Auckland.
