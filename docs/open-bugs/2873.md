Source: https://github.com/litedb-org/LiteDB/issues/2873 (open on 2026-09-13).

by itself it does not reproduce the original deserialization failure. On
2026-09-14, the complete #2298 report consolidated into this issue was retrieved
with `gh`, including its `QuantityRange<Mass>` model, init-only members,
`System.Enum`-typed property, and JSON-based custom constructor.

`Issue2873_ReportedModelTests` now retains that concrete model and constructor
path. Two distinct ranges and enum values are inserted and independently
reopened as raw BSON. Directly invoking the reporter's constructor on the stored

The test uses existing `Ctor(factory)` when no constructor-only API exists, so
its current failure is the actual reported exception. Once an explicit opt-in
is available it exercises that mode and requires both returned rows to be the
exact factory instances with their original ranges and enum values. The separate
compatibility test still requires legacy member population to remain unchanged.

Dev `a50661a9`, Linux/.NET 8: **2 failed, 1 passed**. The failures separately
identify the original model's runtime error and the proposed API's absence.
The concrete model test targets .NET Core, as does the existing upstream #2298
test, because it preserves the reporter's init-only/System.Text.Json model.

## Contract and independent checks

Constructor-only materialization must be an explicit opt-in while the existing `Ctor(factory)` behavior remains compatible. The regression discovers either plausible public API with reflection—`CtorOnly(factory)` or `Ctor(factory, populateMembers: false)`—so the test compiles before the API exists and reports its absence as the actual failure. Only after configuring that opt-in does it require exactly one factory/constructor call, zero mapped-setter calls, a normalized name, an upgraded revision, successful validation, and a matching constructor-computed integrity stamp.

A complementary compatibility control registers the existing one-argument `Ctor(factory)` and requires all three mapped setters to run exactly once after the factory, replacing constructor transformations with the raw stored values. Both paths seed and reread independently authored BSON containing whitespace/lowercase text and a pre-upgrade revision. Consequently, changing existing `Ctor(factory)` semantics, skipping all population globally, ignoring the new option, or merely preserving coincidentally equal values cannot make both tests green.
