# Issue 1325: creating a database without a password

Source: https://github.com/litedb-org/LiteDB/issues/1325 (open on 2026-09-14).

The report constructs `EngineSettings` with `Password = ""`, wraps a new
`LiteEngine` in `LiteDatabase`, and says only that it did not work. The maintainer
recommends `Password = null`. There is no exception, file, or failing operation.

`Issue1325_Tests` preserves that constructor path and checks null, empty, and
nonempty passwords. It inserts two different records, updates one, checkpoints,
closes, inspects the encryption marker directly, and reopens through the separate
connection-string API. Exact IDs and both payloads must survive. This prevents
empty construction, ignored writes, or ignoring the password from passing.

On current dev, null creates a plaintext file. Empty and nonempty strings both
create encrypted files through this API, matching the maintainer's instruction
to use null to disable encryption. These tests cover fresh files only. They do
not claim to change the encryption of a pre-existing file, nor identify what
failed in the underspecified original report.

```sh
dotnet test LiteDB.Tests/LiteDB.Tests.csproj -c Release -f net8.0 \
  -p:TestingEnabled=true --settings tests.runsettings \
  --filter FullyQualifiedName~Issue1325
```
