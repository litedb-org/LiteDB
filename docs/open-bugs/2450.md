## Executed cases

- Failed: `Issue2450_Tests.Repeated_rebuild_keeps_one_current_readable_backup_and_preserves_unrelated_files`
  - The first generation passed its independent current/backup row ledgers and exact file inventory.
  - The second generation had an extra `data-backup-1.db` instead of replacing the one canonical `data-backup.db`.
- Failed: `Issue2450_Tests.Repeated_rebuild_with_live_wal_replaces_both_owned_backups_without_losing_generations`

Both cases create `data-backup-manual.db` before the first rebuild and assert its exact contents after every rebuild and independent reopen. This catches a wildcard cleanup that makes the backup count green by deleting user-owned same-prefix files. They also assert the complete directory inventory, exact `_id`/generation/ledger values in the rebuilt database and backup streams, and a changed backup byte generation, so retaining a stale canonical backup cannot satisfy the lifecycle assertion.
