# Issue 2869: implicit numeric widening unboxes the wrong CLR type

Source: https://github.com/litedb-org/LiteDB/issues/2869 (open on 2026-09-13).

## Contract and independent checks

Each persisted BSON `Int32` boundary value must implicitly widen to the same `long` and `double` value without changing its BSON type. A complementary control proves native `Int64`/`Double` conversions still work and strings such as `"42"` are not silently parsed as numbers. That closes both easy cheats: storing every number as a wider type and using an indiscriminate `Convert` operation.

## Observed on dev

Base: `094f2b8564d65ae37951e4d15104c624c53dafdd`; Release, .NET 8, Linux.

Run: `dotnet test LiteDB.Tests -c Release -f net8.0 -p:TestingEnabled=true --settings tests.runsettings --filter FullyQualifiedName~Issue2869_`.

All five widening cases fail with `InvalidCastException` at the implicit `Int64` conversion; the independent native/non-numeric control passes. Assertions describe corrected behavior and are neither skipped nor inverted.
