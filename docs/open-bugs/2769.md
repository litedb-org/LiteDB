# Issue 2769: [BUG] [Crash / unchecked exception] Non-Int32-backed enums can abort serialization with EnumAsInteger=true

Source: https://github.com/litedb-org/LiteDB/issues/2769 (open on 2026-09-12).

## Contract and independent checks

All eight CLR enum backing types; independently authored integer BSON; raw persisted values after reopen. The UInt64 coverage crosses the Int64 boundary with three distinct bit patterns, including `UInt64.MaxValue`, and hard-codes their expected BSON Int64 bit representations. A typed ledger also checks direct document mapping, persistence and reopen, exact value and marker order, indexed LINQ equality (including duplicate cardinality), raw BSON values, and raw equality queries. A below-boundary UInt64 row is retained as a healthy control, so a fix limited to values representable as positive Int64 cannot make the test green.
