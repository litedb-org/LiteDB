## Exact original exception under Mono (2026-09-15)

The retained two-term predicate workload now reproduces the exact
`Dictionary.Enumerator.MoveNext -> BsonDocument.CopyTo -> IndexCost..ctor`
`InvalidOperationException` on **5.0.2 under Mono 6.12.0.182, 3/3 attempts**.
The same Mono workload passes **3/3 on 5.0.5** and **3/3 on dev `a50661a9`**.
GitHub Actions Ubuntu 22.04 and 24.04 each independently reproduce 3/3 historical
attempts and pass 3/3 dev attempts.

Eight readers have private parameter documents and query a cached compound
predicate during bulk inserts. All query result and parameter controls remain
assertions. Before propagating a query failure, the test checks all 1100 committed
rows, reopens, performs a recovery write, and reopens again. Identical reader
parameter values isolate the enumeration error from the separate value-sharing
race. The .NET 8 suite also runs this scenario, alongside the original different-
parameter control. No query runs concurrently with database disposal.

The 5.0.2 .NET 8 comparison still stops at incorrect query IDs during its sequential
warm-up; that different failure is not counted as proof. The confirmed Mono
comparison removes #1472 from the unconfirmed inventory. This is a minimized
reproduction of the original query stack, not the later disposal report.
