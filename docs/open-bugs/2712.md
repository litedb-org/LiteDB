# Issue 2712: intermittent persisted-vector update

The exact historical source from the reported CI failure,
`21d8e2103496d01eff0caeee2d5133908e793587`, reproduced on 2026-09-15:
**2 failures in 300 cases across 100 fresh processes**. Processes 44 and 66 each
failed one case with `Expected mapped.Id to be 8, but found 7.`
The earlier 20-process experiment had passed, so it was insufficient to dismiss
this intermittent defect.

The retained test restores the historical real-file setup. The later upstream
test switched to `MemoryStream`; merely calling its body had lost that coverage.
It retains the original vector seeds, dimensions spanning multiple data blocks,
index creation, complete vector updates, checkpoint, and reopen. It independently
walks the graph to compare stored vectors with expected document identities,
requires every acknowledged node to remain reachable, checks persisted vector
bits, then requires each vector to find itself at zero distance.

```sh
python3 scripts/regressions/issue_2712.py \
  --source-ref 21d8e2103496d01eff0caeee2d5133908e793587 \
  --attempts 100 --output /tmp/issue2712-historical
python3 scripts/regressions/issue_2712.py \
  --attempts 100 --output /tmp/issue2712-dev
```

The dev comparison at unchanged production source `a50661a9` passed all 300
cases in 100 fresh processes. This is evidence that the historical defect may
be fixed, not proof that every timing/random graph configuration is safe.
The driver retains individual TRX files, process counts, and exact failures.
Missing cases, skipped cases, timeouts, and unrelated failures are harness errors.
The three test cases also remain in the normal xUnit suite.
