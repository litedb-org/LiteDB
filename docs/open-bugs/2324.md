## Manual correction

Reapplying Id to the same mapped member no longer resets its field name or
AutoId setting first. It assigns the requested final settings directly, so
concurrent serialization never sees that member temporarily renamed away from
_id. A genuinely different selected ID still restores the old member through
the configured field-name resolver.

The retained 50,000-iteration race and deterministic repeated-ID/resolver and
ID-switch controls pass. This fixes repeated configuration of the same mapping;
it does not make arbitrary concurrent schema changes atomic. Configure changes
to member selection or other mapping options before database use.
