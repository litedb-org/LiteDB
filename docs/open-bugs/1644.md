# Issue 1644: Query.Or construction cost

Source: https://github.com/litedb-org/LiteDB/issues/1644

ReproRunner confirms excessive construction cost on both NuGet 5.0.21 and dev
`90788bace880f477c9fb52ff7c0da98c9700bdfe` (.NET 8, Linux). A runner success
means that its declared red outcome was reproduced; it does not mean the bug is
fixed.

The fixture builds 100 chained `Query.Or` clauses three times with distinct
literals and measures only expression construction. After each measurement it
checks every disjunct, two non-matches, and the original seed against an
independent integer-range truth table. This prevents a fast implementation from
passing by dropping or broadening terms.

Observed medians on this host:

- NuGet 5.0.21: 777.344 ms.
- Dev: 1,093.714 ms.

Both exceed the deliberately generous 500 ms budget. This is a host-sensitive
performance repro and does not claim the report's historical two-millisecond
baseline. Run it on a quiet machine:

```sh
dotnet run --project LiteDB.ReproRunner/LiteDB.ReproRunner.Cli -c Release -- run Issue_1644_QueryOrCost
```

## Manual correction

AND/OR expression delegates now compile on their first execution. Chained
composition can discard intermediate predicates without compiling each one;
executed predicates retain ordinary compiled throughput. A thread-safe per-expression Lazy
publishes only executed delegates in the global cache; discarded unexecuted
prefix trees remain collectible. Concurrent publishers reuse the winning
compiled entry. Deferred compilation preserves the execution mode
selected during construction. Public expression
sources, parameters, parser validation and short-circuit behavior are preserved.

The unchanged three-round production fixture measures 1,019.446 ms before and
261.853 ms after, below its unchanged 500 ms limit. Every disjunct, seed and
non-match still passes after construction, including the deferred compilation.
This improves repeated construction, not a claim that final first-execution
compilation is free. The package retains its expected reproduction; current
source is expected to return VERIFIED_1644 / exit 10. The absolute wall-clock
threshold remains host-sensitive, so the performance manifest retains flaky
status; a timing mismatch warns and requires inspection.

A weak-reference regression fails with the earlier eager cache publication and
passes when discarded boolean factories remain outside the global cache.
