## Manual correction

Equal-cost range predicates on the same index now prefer the bound nearest the
start of the chosen scan direction. Descending output starts at the tighter
upper bound; ascending output starts at the tighter lower bound. A strict bound
wins an otherwise identical inclusive bound. The remaining predicates stay as
filters, preserving independent multikey ANY witnesses instead of intersecting
them into one scalar interval. Reversing the reported conjuncts therefore picks
the same efficient seek and returns the same exact top results.

Mixed numeric bounds now also support doubles outside decimal's range, infinity
and NaN. Previously these comparisons could throw during a scan or planning.
The existing decimal comparison remains for representable inputs; overflowing
doubles sort outside every finite decimal (NaN sorts first, as Double.CompareTo
does). This extends previously failing comparisons without changing their
previously defined ordering. Large doubles are not compared by rounding decimal
operands to double, which could incorrectly make decimal.MaxValue equal to an
out-of-range double.
