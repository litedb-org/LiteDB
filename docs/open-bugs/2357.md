# Issue 2357: [BUG] Cannot insert duplicate key in unique index '_id'. The duplicate value is '{"$date":"2006-04-02T07:00:00.0000000Z"}'.

Source: https://github.com/litedb-org/LiteDB/issues/2357 (open on 2026-09-12).

## Reproduced with the reporter's date kind

The original attached `NewData.json` contains 480 unique `DateHour` values with
no timezone suffix. The attached model uses `[BsonId] DateTime DateHour` and
passes the deserialized batch to `InsertBulk`. The xUnit test below changed
those IDs to UTC and therefore exercised only a healthy control.

[`Issue_2357_DstDateIds`](../../LiteDB.ReproRunner/Repros/Issue_2357_DstDateIds/README.md)
now preserves the `Unspecified` values and launches isolated timezone processes.
Unspecified/UTC-zone and UTC/Eastern-zone controls pass. In the Eastern zone,
Unspecified 02:00 and 03:00 on 2006-04-02 collide as the reported 07:00Z key.
Independent source ticks, exact stored receipts, a unique secondary index,
rollback, subsequent writes, and reopen are all checked.

Reproduced on 2026-09-14 in both package 5.0.17 and dev `a50661a9`: exact
`BUG_2357_CONFIRMED` outcomes with all controls passing. See the repro README
for the run command and its bounded success/failure contracts.
