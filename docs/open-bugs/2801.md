# Issue 2801: new BsonValue(object) with an array, list or dictionary creates a value whose AsArray/AsDocument is null, causing NullReferenceException in Upsert, ToString and CompareTo

Source: https://github.com/litedb-org/LiteDB/issues/2801 (open on 2026-09-12).

## Observed on dev

Base: `ce2abdff011bc40a37eafa78d1e97dcd8d4a3b00`; Release, .NET 8, Linux.
`11` tests failed and the boxed-scalar compatibility control passed. Every
failure is an explicit assertion that `AsArray` or `AsDocument` must not be
null; the tests themselves do not dereference a null adapter.

The tests permit both resolutions described in the issue. Construction may
either produce a complete BSON collection value, or throw `ArgumentException`
with a message that directs callers to `BsonArray`/`BsonDocument` or
`BsonMapper`. A successful construction must not leave a value that merely
claims `Type == Array`/`Document` while collection operations remain unusable.

## Executed cases

- Four array/list constructor cases failed: `string[]`, fixed-size
  `BsonValue[]`, mutable `List<BsonValue>`, and read-only
  `IList<BsonValue>`. Each includes a CLR null and requires a stable, mutable
  adapter, direct indexing, exact JSON, and null normalization.
- Three dictionary constructor cases failed: mutable and read-only
  `IDictionary<string, BsonValue>`, plus `IDictionary<string, object>`. Each
  requires stable mutable adapters, CLR-null normalization, and
  case-insensitive keys.
- Array and document equality/hash cases failed before comparison. Once an
  adapter exists, primitive count/item/key checks precede symmetric equality,
  unequal controls, and equal-hash assertions.
- The array mapper/binary persistence case failed before mapping. Its later
  ledger checks the mapped CLR array and every primitive after database reopen,
  including exact JSON.
- The document mapper/persistence case failed before mapping. Its later ledger
  checks case-insensitive `_id` replacement, typed mapper output, primary and
  secondary index lookup, exact field count, and primitive values after reopen.
- The boxed `Int32`/CLR-null control passed, preventing a purported fix from
  disabling the entire public `BsonValue(object)` constructor.

Run: `dotnet test LiteDB.Tests -c Release -f net8.0 -p:TestingEnabled=true --settings tests.runsettings --filter FullyQualifiedName~Issue2801_`.
