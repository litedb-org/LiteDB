# Issue 1192: legacy dictionary and exception serialization crashes

Source: https://github.com/litedb-org/LiteDB/issues/1192 (open on 2026-09-13).
The issue has no comments or attached assets.

The issue contains three separate requests. Two report serializer crashes:

- serializing an implementation of non-generic `System.Collections.IDictionary`;
- serializing an `Exception` whose object graph reaches `Delegate` or
  `MemberInfo` values.

The proposed `FromObject`/`ToObject` overloads are API suggestions rather than a
reported failure, so the regression tests deliberately do not assert them.

## Current regression boundary

Plain `Hashtable` serialization was fixed in commit
`8fab56101deca2369a19da5200fe1b2e13ea8980` and already has the passing
`Dictionary_Tests.Serialize_Hashtable` regression. The current implementation
still infers dictionary value type from the concrete type's generic arity. A
generic class with one type parameter that inherits `Hashtable` is a valid
non-generic `IDictionary`, but `Serialize` indexes its one-element generic
argument array at index 1 and throws `IndexOutOfRangeException`.

`Issue1192_Tests.Generic_type_implementing_non_generic_IDictionary_serializes_every_entry`
exercises that remaining form. It requires four heterogeneous entries to retain
their scalar, nested-document, and array values. Returning null, an empty
document, or placeholder values cannot satisfy the test.

`Issue1192_Tests.Exception_with_delegate_and_member_metadata_preserves_ordinary_diagnostics`
uses a thrown exception (so `TargetSite` is populated) inside an envelope that
also contains explicit delegate and `MemberInfo` properties. It does not
prescribe a BSON representation for unsupported reflection metadata. It only
requires serialization not to crash and independently verifies the envelope ID
and label, the exception message, and two user-authored `Exception.Data`
entries. It also proves that serialization does not invoke the supplied
delegate. Thus, ignoring the whole exception, replacing it with null, or
executing callbacks is not a valid way to make the test green.

inverted.
