## CI error classification (2026-09-15)

Windows 2022 and Ubuntu 22.04/24.04 each reproduce the exact primary empty-page
failure **3/3** on 5.0.20 and pass all dev query/persistence assertions **3/3**.
Historical engine shutdown can cause other workers to fail in rollback or index
writes, and concurrent rethrows can overwrite the shared exception's original
stack frames. The classifier now requires the primary error code/message and
an observed engine origin, and permits only the specific documented follow-on
errors alongside it. Those secondary errors alone cannot establish reproduction;
unknown failures and data assertion failures still fail the harness. Six unit
tests check those classification boundaries.

The workflow retains structured process output on failure, replacing the previous
upload path that pointed at already-deleted run directories.

[Captured platform reports](evidence/2825-ci-followup-20260915.json),
[CI run](https://github.com/litedb-org/LiteDB/actions/runs/34943724023).

The full PR matrix exposed another shutdown consequence: a worker committing
dirty pages can reach the already-closed WAL. That trace was rejected rather
than silently counted as proof. The classifier now recognizes the observed
enqueue/persist/commit path only with the primary failure present. The follow-up
run again has **3/3 historical failures and 3/3 dev passes on each of the three
platforms**; all **23 runner unit tests** pass, including rejection of commit-only
errors and incomplete/unrelated stacks.

[Commit-shutdown evidence and original rejection](evidence/2825-commit-shutdown-ci-20260915.json),
[follow-up CI](https://github.com/litedb-org/LiteDB/actions/runs/34948227111).

The next full matrix exposed a worker entering `CreateSnapshot` during delete
after the primary failure had disposed the transaction monitor. The additional
classifier guard requires the exact error type/code/message and the observed
snapshot/delete/automatic-transaction path, together with the primary error.
The three-platform follow-up again records **3/3 historical failures and 3/3
current-source passes per platform**. All **24 runner unit tests** pass; a
disposed transaction alone remains insufficient proof.
