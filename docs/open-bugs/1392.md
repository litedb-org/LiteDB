# Issue 1392: `NotImplementedException` while reading an index key

Source: https://github.com/litedb-org/LiteDB/issues/1392 (open on 2026-09-13).

The issue reports `NotImplementedException` from `BufferSliceExtensions.ReadIndexKey`
during `Upsert`, `Exists`, and index lookup. Reports cover 5.0.0-beta and 5.0.9;
one debugger observation decoded index type byte 59, which is not a valid BSON
type. The issue does not include the failing database, connection string, data
model, or a standalone reproduction. The latest issue comment documents several
unsuccessful reproduction attempts, so the originating corruption is not
confirmed on dev.

## Regression boundary and independent checks

`Issue1392_Tests` models the closest evidence-backed cause without manufacturing
invalid bytes. It creates a database larger than a deliberately small cache,
then runs eight readers alongside two writers. Readers cross-check every selected
record through both its primary key and a unique secondary index against an
immutable in-memory ledger. Writers repeatedly `Upsert` disjoint records while
changing both indexed keys and payload sizes.

The test additionally requires the cache to report actual frame eviction. After
closing and reopening the database, it compares a full collection scan with the
ledger and independently walks the secondary index in order. It also checks
missing-key controls, stored checksums, exact operation counts, cache ownership
accounting, and a 30-second completion bound. Consequently, changing
`ReadIndexKey` to suppress its exception while returning a placeholder or wrong
record cannot make the test pass.

This exercises the cache-reuse mechanism tied to the same symptom in #2817, but
it is a canary, not a reproduction of #1392's unknown original corruption. A
shareable failing `.db` and matching `-log.db` should become a separate fixture;
synthetically changing a type byte to 59 would only prove that corrupted input
reaches the existing guard and would not reproduce the corruption source.

```sh
dotnet test LiteDB.Tests/LiteDB.Tests.csproj -c Release -f net8.0 \
  -p:TestingEnabled=true --no-restore --settings tests.runsettings \
  --filter FullyQualifiedName~Issue1392_
```

Result: `Passed: 1, Failed: 0, Skipped: 0` in one second. Three immediate
`--no-build` repetitions also passed. Compile-only checks for the test project's
`net461` and `net481` targets reached C# compilation but both are independently
blocked by the existing `Issue1162_Tests.cs` missing-runtime-binder error CS0656;
neither reported an error in `Issue1392_Tests.cs`.

The exact original `NotImplementedException` was not reproduced. The passing
canary therefore demonstrates integrity under this bounded cache-recycling
workload; it does not by itself establish that every historical cause of type
byte 59 is fixed.

## Reporter-era package comparison (2026-09-15)

The retained runner passes all three attempts on **5.0.9 and dev `a50661a9`**.
Current source must actually recycle frames under a 64 KiB cache and leave no
lost or pinned pages, in addition to validating every indexed lookup, upsert,
and persisted ID/payload. The originally reported `5.0.0-beta` was also tried:
it failed an indexed missing-row check, without the reported `ReadIndexKey` /
`NotImplementedException` trace. That result is a different failure, not proof
