# Issue 2590: [BUG] InvalidCastException From LiteDB.ObjectId To System.String

Source: https://github.com/litedb-org/LiteDB/issues/2590 (open on 2026-09-14).

## Observed on dev

Base: `dd728e172378c0ab8209e2646e065c2a57b70f36`; Release, .NET 8, Linux.
`4` failed, `0` passed. Assertions describe correct behavior; failures are not skipped or inverted.

## Executed cases

- Failed for `InsertOne`, `InsertMany`, `UpsertOne`, and `UpsertMany`:
  `Issue2590_Tests.Empty_string_ids_are_addressable_or_rejected_before_any_write`.
  All four paths leaked `InvalidCastException` instead of either providing usable string ids or
  rejecting the incompatible mapping with `LiteException.DATA_TYPE_NOT_ASSIGNABLE`.
- `InsertOne` additionally committed a BSON `ObjectId` target before throwing. A fresh observer
  found the otherwise unaddressable row and the database bytes differed from the checkpointed
  baseline. The enumerable insert/upsert paths rolled their transactions back, but still leaked
  the implementation exception.
- The regression runs each operation with two targets and preserves three independently checked
  controls: an ordinary string id plus BSON String and BSON ObjectId ids with identical text.
  The success contract requires generated ids to remain distinct BSON strings across return-value,
  entity, raw, typed, expression, and reopened queries; the rejection contract requires an exact
  public diagnostic and byte-for-byte atomicity.

Run: `dotnet test LiteDB.Tests -c Release -f net8.0 -p:TestingEnabled=true --settings tests.runsettings --filter FullyQualifiedName~Issue2590_`.
